# 混合精度与 Scaling 完全指南

> 目标：搞懂 FP32/TF32/FP16/BF16/FP8/INT8 各自为什么出现，以及 scaling（缩放）到底怎么一步步做。
> 面向：知道 CUDA 基础但对精度格式和量化不熟的人。

---

## 第一部分：浮点数怎么表示（基础）

任何浮点数都是这个结构：

```text
值 = (-1)^符号 × 1.尾数 × 2^(指数 - bias)

  符号位：正负
  指数位：管"范围/量级"（能多大多小）
  尾数位：管"精度"（多少有效数字）
  bias  ：偏移常数 = 2^(指数位-1) - 1，让指数能表示负数
```

一句话记忆：**指数管范围，尾数管精度。**

各格式的位分配：

| 格式 | 总位 | 符号 | 指数 | 尾数 | 最大值(约) | 有效数字 |
|------|-----:|-----:|-----:|-----:|-----------:|---------:|
| FP32 | 32 | 1 | 8 | 23 | 3.4e38 | ~7 位 |
| TF32 | 19* | 1 | 8 | 10 | ~3.4e38 | ~3 位 |
| FP16 | 16 | 1 | 5 | 10 | 65504 | ~3 位 |
| BF16 | 16 | 1 | 8 | 7 | 3.4e38 | ~2 位 |
| FP8 E4M3 | 8 | 1 | 4 | 3 | 448 | ~1 位 |
| FP8 E5M2 | 8 | 1 | 5 | 2 | 57344 | <1 位 |
| INT8 | 8 | — | — | — | 127 | 整数 |

*TF32 物理仍占 32 位空间，只是乘法用 19 位有效精度。

## 第二部分：每种格式为什么出现

### FP32（基准）
```text
标准单精度，7 位有效数字，范围 10^±38。
问题：大模型下太贵——每个数 4 字节，显存/带宽/算力成本高。
```

### FP16（2017 起，混合精度训练）
```text
为什么出现：把 32 位砍到 16 位，省一半显存/带宽，Tensor Core 加速。
做法：5 指数 + 10 尾数。
问题：指数只有 5 位 → 范围小（10^±5）→ 训练梯度容易溢出/下溢。
     → 需要 loss scaling（把 loss 乘个大数防梯度下溢）。
```

### BF16（Brain Float，Google 提出）
```text
为什么出现：解决 FP16 范围小的问题。
做法：8 指数（和 FP32 一样）+ 7 尾数 = 截断版 FP32。
好处：范围同 FP32（10^±38）→ 训练不溢出，不用 loss scaling。
代价：只有 7 位尾数，精度比 FP16 还粗，但训练能容忍。
结论：现代大模型训练首选 BF16（范围优先，精度够用）。
```

### TF32（NVIDIA，Ampere/A100）
```text
为什么出现：想让 FP32 的 GEMM 也能用 Tensor Core 加速。
做法：FP32 输入，但乘法时把尾数砍到 10 位（保 8 位指数）。
好处：范围同 FP32，精度略降，Tensor Core 吞吐是 FP32 CUDA core 的 ~8 倍。
      （实测 cuBLAS：FP32 CUDA core 17314 GFLOPS → TF32 88301 GFLOPS）
关键：普通 FP32 kernel 不会自动走 TF32，要库/API 开启（CUBLAS_TF32_TENSOR_OP_MATH）。
```

### FP8（Hopper/H100，2022 起）
```text
为什么出现：大模型越来越大，FP16 还是贵 → 再砍一半到 8 位。
好处：省一半显存、有效带宽翻倍、Tensor Core FP8 吞吐更高。
两种：
  E4M3（4指数3尾数，最大448）：精度优先 → 前向/权重
  E5M2（5指数2尾数，最大57344）：范围优先 → 梯度
问题：范围太窄 → 直接转会溢出/下溢 → 必须 scaling（下面详解）。
```

### INT8（整数量化，推理常用）
```text
为什么出现：推理时权重/激活用 8 位整数，比浮点更省、更快。
做法：不是浮点，是"定点"——用一个 scale 把浮点映射到整数 [-127,127]。
好处：推理省显存带宽，硬件 INT8 吞吐高。
问题：整数没有指数 → 只能表示均匀间隔的值 → 也需要 scale（+可能 zero-point）。
用途：INT8 推理（GPTQ/AWQ 等量化方法）。
```

## 第三部分：Scaling 到底怎么做（重点，一步步）

### 为什么需要 scaling
```text
FP8 E4M3 最大只有 448，但神经网络的值可能是 0.001 或 3000。
直接转 FP8：
  3000 → 超过 448 → 溢出变 inf
  0.001 → 太小 → 下溢变 0
数据全毁。
解法：先把数据"缩放"到 FP8 能表示的范围，算完再缩回来。
```

### Scaling 五步（配具体数字）

假设有个张量 `x = [0.6, 0.02, -0.45, 0.003]`，要用 FP8 E4M3（最大 448）存。

```text
━━━ 第1步：统计 amax（最大绝对值）━━━
amax = max(|0.6|, |0.02|, |0.45|, |0.003|) = 0.6

━━━ 第2步：算 scale（缩放因子）━━━
让最大值缩放后刚好到 FP8_MAX：
scale = FP8_MAX / amax = 448 / 0.6 ≈ 746.7

━━━ 第3步：缩放 + 量化（转 FP8）━━━
每个数 × scale，再转 FP8：
  0.6   × 746.7 = 448     → FP8 存 448（刚好满）
  0.02  × 746.7 = 14.9    → FP8 存 ~15
  -0.45 × 746.7 = -336    → FP8 存 ~-336
  0.003 × 746.7 = 2.24    → FP8 存 ~2.24
现在所有值都落在 [-448, 448]，且小值被放大了 → 有精度！
q = FP8([448, 15, -336, 2.24])

━━━ 第4步：用 FP8 做计算（如 GEMM）━━━
D = q_A × q_B   （Tensor Core FP8 矩阵乘）
注意：结果里带了 scale_A × scale_B 的因子

━━━ 第5步：反缩放（除回 scale）━━━
真实结果 = D / (scale_A × scale_B)
把缩放的倍数除掉，还原成真实数值（用 FP32 存结果）
```

### 关键理解
```text
1. scaling 换的是"相对精度"：不管原始多大/多小，
   缩放后都落在 FP8 甜蜜区，用 8 位表示"相对大小"。
2. 448 是绝对上限不重要，重要的是"缩放后落在范围内"。
3. 大值 clip 到 448（防溢出），小值被放大（获得精度）。
4. 累加用高精度（FP32）→ 减少误差累积。
```

### 溢出控制（clip / saturate）
```text
缩放后个别值仍可能 > 448（比如 amax 估计不准）：
  → clip 到 ±448（饱和），防止变 inf
q = FP8(clip(x * scale, -448, 448))
```

## 第四部分：scale 的粒度（per-tensor vs per-block）

### per-tensor（整个张量一个 scale）
```text
简单：一个张量算一个 amax、一个 scale。
问题：异常值（outlier）毁精度。
  例：x = [0.01, 0.02, 0.015, 1000]
  amax = 1000 → scale = 448/1000 = 0.448
  那些 0.01 × 0.448 = 0.0045 → 太小，FP8 存不出精度 → 变 0
  一个异常值把其它所有小值压死了。
```

### per-block（每小块一个 scale）
```text
细粒度：把张量切成小块（如每 128 个元素），每块独立算 scale。
好处：异常值只影响它那一块，其它块精度不受影响。
代价：scale 数量多 → 要高效存储/布局（layout/swizzle）。
DeepSeek 用 per-block FP8，就是为了精度。
```

### per-channel（每通道一个 scale）
```text
介于两者之间：每个通道（如每列）一个 scale。
适应不同通道的值域差异，常用于权重量化。
```

对比：

| 粒度 | 优点 | 缺点 |
|------|------|------|
| per-tensor | 元数据少、简单 | 异常值毁全张量精度 |
| per-channel | 适应通道差异 | 元数据中等 |
| per-block | 局部适配好、精度高 | scale 多，需高效 layout |

## 第五部分：为什么低精度可行（底层逻辑）

```text
神经网络对数值精度不敏感：
1. 训练有噪声（SGD、dropout、数据噪声）→ 少量数值误差被淹没。
2. 矩阵乘是大量累加 → 单值误差随机、部分抵消（累加用 FP32）。
3. 推理最终是"选最大/排序"做决策 → 正确答案分数明显领先，
   低精度的小扰动改不了排序 → 结果照样对。

所以能一路砍：FP32 → FP16/BF16 → FP8 → FP4，效果几乎不降。
推理比训练更能容忍低精度（推理误差不累积，训练误差累积多轮）。
```

## 第六部分：FP8 为什么难（工程视角）

```text
难点不在"转换指令"，而在整条数据流：
  统计 amax → 生成 scale → 缩放量化 → GEMM → 反缩放 → epilogue

每步都有工程决策：
  - scale 是否限制为 2 的幂（方便硬件）
  - 用当前 amax 还是历史窗口（delayed scaling，避免每次都扫）
  - scale 存什么精度、怎么布局才能被 Tensor Core 高效读
  - NaN/Inf/异常值怎么处理
  - per-tensor / per-channel / per-block 怎么选

这就是 DeepGEMM、Transformer Engine 存在的意义：
把 FP8 的整条 scaling 数据流做成高效、正确的 kernel。
```

## 第七部分：面试口述

### Q：为什么有这么多精度格式？
```text
都是"用精度换效率"，在范围/精度/速度间权衡：
  FP32 基准 → FP16 省一半但范围小 → BF16 保范围砍精度（训练首选）
  → TF32 让 FP32 GEMM 走 Tensor Core → FP8 再省一半（需 scaling）
  → INT8 整数量化（推理）。
指数管范围、尾数管精度，砍哪个取决于场景对什么敏感。
```

### Q：scaling 怎么做？
```text
FP8 范围窄（E4M3 最大 448），直接转会溢出/下溢，所以要 scaling：
  1. 统计 amax = max|x|
  2. scale = 448 / amax
  3. 量化 q = FP8(clip(x * scale, -448, 448))
  4. 用 FP8 做 GEMM
  5. 结果除回 scale（反缩放），FP32 存
关键是相对精度不是绝对范围。异常值会毁 per-tensor scale，
所以用 per-block scale（DeepSeek 做法），代价是 scale 多需高效 layout。
```

### Q：为什么低精度能用？
```text
神经网络对精度不敏感：训练有噪声、矩阵乘累加抵消误差、
推理是选最大做决策（分数领先，小扰动不改排序）。所以能砍位数换效率。
```

```text
范围大小（指数位）：FP32=BF16=TF32 > FP16 > FP8-E5M2 > FP8-E4M3
精度高低（尾数位）：FP32 > TF32=FP16 > BF16 > FP8-E4M3 > FP8-E5M2

用途：
  训练：BF16（范围）/ FP8+scaling（省成本，DeepSeek）

  GEMM 加速：TF32（FP32 免改代码走 Tensor Core）
```
