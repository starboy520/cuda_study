# CUDA 面试核心题库答案内联重排设计

## 背景

当前《CUDA 面试核心题库》的 Q1–Q40 主答案已经位于题目下方，但追问答案集中在附录 A、B，第 15 章参考答案集中在附录 C。复习时需要在正文和附录之间来回跳转，且同一知识点存在重复内容。

## 目标

将所有答案移动到对应问题正下方，使文档可以按章节从上到下连续复习，同时保留现有技术内容、难度标签、常见误区、项目证据和有效链接。

## 非目标

- 不重写 CUDA 技术结论或项目实测数据。
- 不增加新的面试题。
- 不拆分为多个章节文件。
- 不使用 HTML 折叠标签，以保证 Markdown 预览、搜索和导出兼容性。

## 文档结构

### Q1–Q40

每题统一采用以下顺序：

1. 难度。
2. 15 秒回答。
3. 1 分钟展开。
4. 追问 1 及紧随其后的参考答案。
5. 追问 2 及紧随其后的参考答案。
6. 常见误区。
7. 项目证据。
8. 相关资料（仅在存在直接相关资料时添加）。

追问不再使用只有问题的编号列表，而改为独立的“追问 1”“参考答案”结构，确保答案与问题在视觉和语义上绑定。

### 第 15 章

- 项目深挖题改为“问题 → 参考回答”的连续结构。
- 高频手写题保留总览表，并在其后放置各题的答题骨架和自检点。
- 三档模拟面试在每个考察项后直接给出参考思路。
- 保留项目回答四段式模板和公开 GEMM 一句话版本，作为本章末尾的通用收束方法。

### 附录处理

附录 A、B、C 的内容迁移完成后全部删除，不保留重复备份。正文中的“见续篇”“见附录”等过时提示一并删除或改写。

## 链接策略

- 保留每题现有的“项目证据”链接。
- 优先复用仓库中的教材、实验、性能记录和公开作品集链接。
- 在确有帮助时增加 NVIDIA 官方文档链接；不为凑数量给每题机械添加链接。
- 保留文末官方资料索引，作为跨章节入口。
- 修改后运行仓库的 Markdown 链接检查，修复由重排引入的内部链接问题。

## 内容保护原则

- 迁移以原文为主，不擅自美化项目数据或扩大结论适用范围。
- 保留“未实测”“旧口径作废”“不能跨架构泛化”等边界说明。
- 统一术语和标签格式，但不进行与本次复习结构无关的大规模改写。
- 避免一个答案在正文中出现两次。

## 验收标准

1. Q1–Q40 的每个追问后都紧跟对应参考答案。
2. 第 15 章中的项目深挖、手写题和模拟面试都有就地参考答案。
3. 附录 A、B、C 已删除，且没有丢失其有效内容。
4. 文档中不存在“见续篇”“待确认后补充”等失效提示。
5. 标题层级、列表、表格和代码块符合 Markdown 规范。
6. 仓库 Markdown 链接检查通过，或仅剩与本次修改无关的已知问题。
7. Git diff 主要体现内容移动、标题调整和链接补充，不改变既有技术事实。

## 实施边界

本次只修改《CUDA 面试核心题库》及必要的设计/计划文档。若发现原答案存在明显技术错误，将单独列出并征求确认，不在格式重排中静默修改。
