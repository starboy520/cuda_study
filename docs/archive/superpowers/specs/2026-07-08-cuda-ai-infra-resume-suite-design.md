# CUDA 与 AI Infra 简历套件设计说明

## 1. 目标

基于候选人的真实工作经历、公开 CUDA 学习仓库和近期个人项目，生成一套面向高级工程师/资深 IC 岗位的中文 ATS 简历。

简历套件既要利用候选人 12 年 C++、高并发系统、搜索/广告和在线推理经验，也要诚实说明 CUDA 属于 2026 年开始的个人性能工程实践，不能将学习项目包装成商业生产经验。

## 2. 候选人定位

统一目标职级为高级工程师或资深个人贡献者，不直接定位为 CUDA 架构师。

核心转型叙事为：

```text
大型 C++ 在线系统与性能优化
→ TensorFlow C++ 在线推理和检索/排序服务
→ A100 CUDA kernel、算子与 GPU 性能工程
→ CUDA + AI Infra 高级工程师
```

候选人的团队管理经历保留为跨团队推动和技术领导力证据，但不作为简历主轴。

## 3. 时间线处理

- 2025.01～2025.11：依图科技架构师；
- 2025.12～2026.03：个人休整，不单独建立简历条目；
- 2026.04～至今：CUDA 性能工程个人项目与全职学习实践。

个人项目必须明确标注为个人项目，不能归入任何公司经历。

## 4. 输出文件

最终生成七份 Markdown：

1. `戚成杰_事实母版.md`
2. `戚成杰_CUDA与AI_Infra高级工程师_通用版.md`
3. `戚成杰_CUDA性能优化高级工程师.md`
4. `戚成杰_LLM推理算子高级工程师.md`
5. `戚成杰_AI_Infra性能工程师.md`
6. `戚成杰_GPU_CUDA系统高级工程师.md`
7. `岗位版本差异与投递建议.md`

事实母版用于维护全部真实素材，不直接投递。通用版用于招聘平台、猎头和没有明确 JD 的投递；四份专项版用于岗位方向明确时投递。

## 5. 共同简历结构

六份简历采用相同的 ATS 结构：

1. 姓名、联系方式与 GitHub；
2. 目标职位；
3. 专业摘要；
4. 核心技术能力；
5. CUDA 性能工程个人项目；
6. 工作经历；
7. 教育背景。

不使用 Markdown 表格、复杂多栏布局、图片、照片、年龄、婚姻状态或无关个人信息。投递版控制在约两页的信息密度，事实母版可以更长。

## 6. 各版本重点

### 6.1 CUDA 与 AI Infra 通用版

作为默认投递版本，平衡呈现：

- 12 年 C++ 与高性能在线系统经验；
- TensorFlow C++ serving 和模型推理优化；
- A100 CUDA kernel、GEMM、Attention 与 Tensor Core 实践；
- Nsight Compute、Roofline、PTX/SASS 和正确性工具；
- 延迟、吞吐、资源、稳定性与工程交付。

### 6.2 CUDA 性能优化版

优先展示 CUDA 执行与内存模型、warp 原语、GEMM 优化阶梯、shared/register tiling、向量化、异步流水、Roofline、Nsight Compute、Compute Sanitizer 和 PTX/SASS。

### 6.3 LLM 推理算子版

优先展示 Attention、Online Softmax、教学版 FlashAttention、GEMV、RMSNorm、WMMA/Tensor Core、prefill/decode 和算子融合，并连接既有 TensorFlow C++ 在线推理经验。

尚未完成或尚未重新验证的 RMSNorm、Dequant GEMV、CUDA Graph 练习不能写成已经完成的量化成果。

### 6.4 AI Infra 性能版

优先展示 C++ serving、brpc、TensorFlow、搜索/广告在线系统、模型延迟和资源优化，以及 GPU profiling 与 CUDA kernel 能力。这是和既有职业经历衔接最自然的版本。

### 6.5 GPU/CUDA 系统版

优先展示 C++ 系统能力、内存与同步模型、stream/pinned memory、异步执行、GPU 架构、编译链、PTX/SASS、性能测试和跨架构意识，弱化 ML 业务细节。

## 7. 事实和证据边界

所有表述分为三层：

### 7.1 商业经历

只使用候选人提供的公司、项目、职责和指标。对明显需要口径说明的数字，在事实母版中记录面试时应准备的计算方式和背景，不擅自扩大因果关系。

### 7.2 仓库历史证据

CUDA 项目可使用已存在且可解释的结果，例如：

- A100 FP32 GEMM 优化阶梯和性能对照；
- WMMA FP16 GEMM 及 HMMA 指令证据；
- Attention/Online Softmax 和 `cp.async` 双缓冲实验；
- GEMV 线程映射与访存优化；
- Nsight Compute、Roofline、Compute Sanitizer、PTX/SASS 分析流程。

旧笔记中的 reduction“91% 峰值带宽”存在字节口径问题，不进入简历。

### 7.3 待重新验证内容

未完成、只有脚手架或尚未在当前环境重跑的内容，写入事实母版的“候选素材/待验证”区域，不进入投递版的成果要点。完成 14 天突击并重新取得证据后，才能升级到投递版。

## 8. CUDA 项目写法

个人项目统一标明：

```text
CUDA 性能工程个人项目｜2026.04～至今
GitHub: https://github.com/starboy520/cuda_study
环境与重点：NVIDIA A100 / CUDA C++ / Nsight Compute / PTX/SASS
```

项目要点采用“动作 + 技术方法 + 可验证结果 + 条件”的结构。不能使用“精通 CUDA”“生产级 FlashAttention”“CUTLASS 专家”等无法支撑的标签。

## 9. ATS 和篇幅规则

- 使用标准标题：专业摘要、技术能力、项目经历、工作经历、教育背景；
- 使用纯文本项目符号，不使用表格和图形；
- 技能关键词必须能由工作或项目支撑；
- 每条经历优先使用动作、技术方法和量化结果；
- 最近、最相关的经历获得更多篇幅，百度早期经历适度压缩；
- 不写第一人称，不添加“可提供推荐人”等过时信息；
- 中文和英文缩写并列时保持行业常用写法，例如 Nsight Compute、PTX/SASS、CUDA Graph。

## 10. 投递建议文档

`岗位版本差异与投递建议.md` 包含：

- 六份简历的使用场景；
- 当前最适合投递的岗位和风险较高的岗位；
- 可写“掌握”、应写“熟悉”和只能写“了解”的能力；
- 当前缺口与完成 14 天突击后的升级项；
- 得到具体 JD 后的关键词替换清单；
- 面试中需要准备的商业指标与 CUDA 项目证据。

## 11. 隐私与文件交付

最终简历包含真实手机号和邮箱，因此不能提交到公开 Git 仓库。

处理方式：

1. 在远程工作区创建本地私有目录 `resume_private/`；
2. 使用 `.git/info/exclude` 在当前克隆中排除 `resume_private/`，不修改共享 `.gitignore`；
3. 最终 Markdown 和压缩包均保存在 `resume_private/`；
4. Git 提交只包含不含个人联系方式的设计说明和实施计划；
5. 交付时提供远程工作区文件链接，用户下载到个人电脑后再通过邮箱发送。

不得把真实联系方式复制到设计说明、实施计划、提交信息或其他 tracked 文件。

## 12. 验收标准

- 七份输出文件全部存在；
- 通用版和四份专项版有明显但真实的岗位差异；
- 各版本的公司、时间、技术和数字相互一致；
- CUDA 内容明确是个人项目，不冒充商业生产经验；
- 所有 CUDA 量化成果能映射到仓库证据或明确标记待验证；
- 未完成内容不写成已完成；
- 投递版符合 ATS 结构并控制在约两页信息密度；
- 手机号和邮箱只出现在 `resume_private/`；
- `git status` 不显示 `resume_private/` 文件；
- 压缩包可以从远程工作区下载。
